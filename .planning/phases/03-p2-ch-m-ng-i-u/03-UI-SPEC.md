| Place | Tokens | Rule |
|-------|--------|------|

`scoreLevel` (RES Pattern 8; location `apps/web/lib/scoreLevel.ts` — RES Open Question 7): `scoreLevel(score01: number | null): 'good' | 'ok' | 'bad' | 'unrated'`, `null → 'unrated'`, otherwise round to the **displayed integer first** (`Math.round(score01 * 100)`: 79.6 shows `80` and is green), then `≥ 80 good · ≥ 60 ok · else bad`. A companion lookup maps level → **literal** Tailwind class strings (`text-score-good-text`, `bg-score-good`, …) so Tailwind's JIT sees them; components never build class names dynamically and never hardcode a score hex. Colour is **never** the only signal: every coloured score has its number next to it.

Identity colours (teal = Bản gốc, orange = Bạn) — still reserved exclusively for source identity. New uses, all of which denote "the original" or "you":
- `IntonationChart`: original contour `--original`, your contour `--you`, legend swatches, stress bars (original bar `--original`, your bar `--you`).
- `TipList` / sentence highlight for `STRESS_MISMATCH` only: the word that should be stressed (from the original) uses `--original` underline and `--original-soft` fill; the word you stressed instead uses `--you` underline and `--you-soft` fill (gap P3-G5).
- Footer `Bản gốc (O)` / `Của bạn (M)` buttons and playback pressed rings (unchanged).

Neutral highlight (no meaning beyond "this is what the tip talks about"): fill `--slate-4` (`#E8E8EC`), underline `--slate-9` (`#8B8D98`, decorative line, the word is also bold). Used for the sentence word and chart `ReferenceArea` for every issue code except `STRESS_MISMATCH`.

Issue marker (new alias tokens, gap P3-G4): `--issue: var(--red-9)` (`#E5484D`), `--issue-text: var(--red-11)` (`#CE2C31`), added to `globals.css` next to the P2-G3 aliases. Used **only** for the `ngắt thừa` ‖ marker and its label in the chart (S3 uses exactly these hexes). `--score-bad` stays score-only and `--destructive` stays failure-only.

Neutral result line (no issue, overall < 80): background `--muted`, text `--muted-foreground` (5.22:1), no border. Not dashed (dashed + grey is the `unrated` / `ref_unclear` language, reserved for Phase 5).

### `AttemptStrip` (S3 top strip)

Flex, `flex-wrap`, `align-items: center`, `gap: 8px 16px`, 13px muted (S3). Order: `Câu {n}` (700, foreground) → one chip per **scored** attempt → right-aligned (`margin-left: auto`) `Mất chữ cuối?` and `IPA` ghost buttons (P1, unchanged).
- Chip = ghost button, 44px high, padding `0 12px`, radius 8, text `Lượt {k} · {score}` where `k` is the **ordinal among scored attempts** (1, 2, 3…, not the raw `attempt` number, so a `no_speech` attempt never leaves a gap — RES Pitfall 10 / Open Question 4) and `score` is `Math.round(overall * 100)`. Score text is **not** coloured (S3 shows plain text). Muted by default; the attempt currently shown has `aria-current="true"`, weight 600 and foreground colour; hover/focus adds `--muted` background.

- Click a chip → the result region shows that attempt's saved `ScoreResult` (`result_json`). While it loads: skeleton (below). The currently shown chip stays visible so the user always knows which attempt they are viewing. A new attempt always becomes the shown one when its result arrives (the user just spoke it).
- Overflow: show at most **6** chips: the 5 most recent plus the best one if it is older (rendered first, ascending order otherwise). Earlier attempts remain stored (Phase 7) but are not listed.

### `TipList`

`ol`, `list-style: none`, flex column, gap 14, 16/1.5. ## Interaction Contract

Shortcut map, focus rules and the machine mapping are the **baseline** from `02-UI-SPEC.md` (`Space`, `R`, `←/→`, `O`, `M`, `B`, `I`, `T`); no new shortcut is added (the chart toggle, attempt chips and tips are mouse/Tab-operable only). Phase 3 specifics:

- Machine shape (PLY-02) is unchanged: `idle → playing → recording → scoring → reviewing`, branches `noVoice` and `error`. Only the `scoring` actor output changes from `AttemptAck` to `ScoreResult`; `onError` with code `no_speech` goes to `noVoice`, any other failure to `error` with `RETRY_UPLOAD`. UI reads `state.value` / `state.context` only. The tip hover, chart open state and the shown-attempt choice are **React state outside the machine**.
- `scoring` row of the shortcut table (replaces P1 "processing"): `Space`, `R`, `←/→`, `O`: ignored; `M`: plays your recording (blob is in memory); `B`: ignored.
- `reviewing`: `Space` starts a new attempt via listening; `R` records immediately (FBK-06). Starting a new attempt never discards earlier results: the strip keeps all scored attempts and re-evaluates `tốt nhất` after the new result arrives. The panel shows the **newest** attempt, not the best.
- Audio buttons apply to the **attempt being shown**: `Bản gốc (O)` always works; `Của bạn (M)` and `Lần lượt cả hai (B)` are enabled iff an in-session recording exists for that attempt, else `aria-disabled` + the tooltip in the copy table (D-11).
- Changing sentence (`←/→`, list click, `Câu tiếp`) resets the shown attempt to that sentence's latest scored attempt (or nothing), clears the tip hover, and keeps the chart open/closed choice.
- Result arrival: no focus move and no scroll jump; the visually hidden `role="status"` message announces it once. `scrollIntoView` for the current transcript row stays `block: 'nearest'` and `behavior: 'auto'`.
- Motion: no animation on the chart (`isAnimationActive={false}`), no result entrance animation; skeleton uses the existing pulse, which the global `prefers-reduced-motion` rule already neutralises.
- Latency feedback: the scoring panel is the only wait indicator; nothing else blocks. If the request is still pending after 5 s the caption changes (copy table). A failed request goes to the `error` panel + persistent toast (REC-03: the recording is never lost).
- Offline/key: scoring needs no API key and no network beyond localhost; the missing-key banner (S1) is unrelated to this phase (tips are templates and carry no "AI" label, FND-05).

Accessibility additions: result region is a labelled `section`; hero indices expose full Vietnamese names; chart exposes `role="img"` text; tips are focusable for parity with hover; the praise/neutral line is `role="status"`; colour never carries meaning alone (number + text beside every score colour).
