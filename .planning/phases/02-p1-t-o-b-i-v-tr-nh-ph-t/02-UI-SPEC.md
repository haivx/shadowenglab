## Spacing Scale

Declared values (named scale, all multiples of 4) — `tokens.md` "Khoảng cách theo bội số 4; giữa các khối lớn 24–32":

| Token | Value | Usage (with mock source) |
|-------|-------|--------------------------|
| xs | 4px | Nav item gap (S1 header), tab gap, `kbd` spacing, icon gaps |
| sm | 8px | Button groups (`PlayerControls` row, S2 actions), chip gaps, form label→input |
| md | 16px | Card grid gap (S1), default stack gap, field-group gap, card inner padding (S1 card body 16) |
| lg | 24px | Section padding (S8 sections 24), S1 main stack gap 24, state-panel padding 24, panel stacks |
| xl | 32px | Page padding (S1/S8 main 32; AppHeader horizontal 32), S3 block gap 32 |
| 2xl | 48px | S3 main horizontal padding (48), major section breaks |
| 3xl | 64px | Page-level spacing (empty-state vertical padding) |

Intermediate multiples of 4 used by the mocks and allowed as-is: **12** (AppHeader vertical padding, banner gap, preview block padding), **20** (large button side padding, `Tạo bài từ YouTube` 20), **28/36/40** (S3 main top/bottom padding 36/40, level meter 40). Any multiple of 4 copied from a mock for layout-only measurement is permitted.

Exceptions (not multiples of 4), kept because they appear in the locked mocks, limited to these uses:
- **2px**: word underline stack gap, segmented-progress gap (`SegmentedProgress` gap 2), border insets.
- **6px**: tag/badge row gap (S1 card badges), progress-bar stack gap (card bar + caption), S2 field stacks (label→input 6).
- **10px**: footer action-bar gap (S3 footer gap 10), S1 card body stack gap (10), S2 actions gap.
- **14px**: banner/callout vertical padding (S1 banner `14px 16px`), S2 range block gap.
- Snapped (mock value → spec value): 18 → 20 (button side padding on `Ghi lại`), 22 → 24 (n/a in P1).

Touch/hit targets (REQ PLY-07, `tokens.md` Nút và thao tác): every labelled action button is **44px** tall (regular) or **48px** (primary action in a bar: `Tạo bài từ YouTube`, `Tạo bài`, `Ghi lại`, `Câu tiếp`, `Huỷ`, URL input). Deviation G4: mock toolbar items at 32/36/38px (Dịch, Sửa câu, Mất chữ cuối?, S3 selects, Kết thúc buổi) are raised to **44px** to satisfy PLY-07. `AppHeader` nav links stay 40px high (navigation, not a practice action) and the Settings icon link is 44×40 as in S1.

## Color

Source: `tokens.css` (values), `tokens.md` "Quy tắc màu". 60/30/10 mapping for this design (no brand accent hue: the "accent" is the near-black primary, by design — "chữ làm phần lớn việc", `design/README.md` nguyên tắc 3).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FCFCFD` (`--background`, slate-1) | Page background |
| Secondary (30%) | `#FFFFFF` (`--card`) · `#F9F9FB` (slate-2) · `#F0F0F3` (`--muted`, slate-3) | White: AppHeader, cards, dialog, control bar, footer, state panels. slate-2: S3 left column, preview block, settings status row. muted: tracks, tab hover, chips, badges neutral |
| Accent (10%) | `#1C2024` (`--primary` / `--foreground`, slate-12) | Reserved list below |
| Destructive | `#E5484D` (`--destructive`, red-9) fills/borders; text `#CE2C31` (red-11) | Failed lesson card border + message, invalid inputs, "Key không hợp lệ", models-missing banner. Never for decorative use |

**Accent (`#1C2024`) reserved for:** (1) solid primary buttons (`Tạo bài từ YouTube`, `Tạo bài`, `Tiếp tục ở câu N`, `Nghe câu mẫu`, `Câu tiếp`, `Ghi lại` in the no-voice panel); (2) the current-sentence marker (3px left border on the transcript row) and the current segment in `SegmentedProgress`; (3) progress fills (lesson progress, job step progress, `Progress` neutral); (4) selected tab border and text; (5) focus ring (`--ring`); (6) the thumb/range of `RangePicker`. It is **not** used for "all interactive elements": outline/ghost buttons use `--input` border and `--foreground` text.

Identity colors (teal/orange) — **reserved exclusively for Bản gốc / Bạn** (`tokens.md`; `CLAUDE.md`):
- Teal (`--original` #12A594, `-text` #008573, `-soft` #E0F8F3, teal-12 #0D3D38 for IPA text): `Bản gốc (O)` button, playing-original chip and its progress fill, `IPA từ audio mẫu` badge and IPA text.
- Orange (`--you` #F76B15, `-text` #CC4E00, `-soft` #FFEFD6): `Của bạn (M)` button, playback-of-your-recording indicator.

Semantic status colors (not scores, not identity):
- Recording `--recording` #E5484D: `Đang ghi` chip fill, 2px panel border, level-meter bars (low bars `--red-7` #F4A9AA). `tokens.md`: "Đỏ còn dùng cho trạng thái đang ghi".
- Warning (`--warning-soft` #FFF7C2, `--warning-border` #E9C162, `--warning-text` #AB6400): no-key banner, mic-denied banner, no-voice panel alert, "Có nhạc nền" badge.
- Success (G3 alias, same hex as score-good): `--success` #30A46C, `--success-text` #218358, `--success-soft` #E6F6EB: "Xong" step labels, "Audio sạch" badge, "Key hợp lệ", "Sẵn sàng" model status.
- Destructive soft/border (G3 alias): `--destructive-text` #CE2C31, `--destructive-soft` #FEEBEC, `--destructive-border` #F4A9AA.
- "Practiced" (D-08, G23): neutral gray `--muted-foreground` (#60646C) dot in the transcript list and neutral gray segments in `SegmentedProgress`; not-yet-practiced = `--slate-4` (#E8E8EC) segments / no dot; current = slate-12.

**Score colors (`--score-*`) and `scoreLevel()` are NOT used anywhere in P1** (D-08, `design/README.md`: scores always go through `scoreLevel()`). Do not apply red/yellow/green to sentence-list dots, progress segments or cards. The `score-*` entries exist in `tailwind.config.ts` for Phase 3 but P1 code must not reference them (add a grep check in verification: no `score-` class in P1 components).

Contrast: all small text on white uses slate-11 or darker (≥ 4.5:1, `tokens.md`). Where mocks use slate-9 (#8B8D98) for small text (translation text 13px, inactive timestamps 11px, helper 12px) use `--muted-foreground` instead (G20). Slate-9 stays only for the 12/700 uppercase group label, which `tokens.md` assigns it explicitly.

Mock-hex → token (so executors do not hardcode): `#FCFCFD`=background · `#FFFFFF`=card · `#F9F9FB`=slate-2 · `#F0F0F3`=muted · `#E8E8EC`=border · `#E0E1E6`=slate-5 (footer top border) · `#CDCED6`=input · `#60646C`=muted-foreground · `#1C2024`=foreground/primary · `#111316`=`--video-bg` (G3, video/thumbnail letterbox) · `#B9BBC6`=slate-8 (text on video).

## Interaction Contract

**Shortcut map** (REQ PLY-07; every shortcut also has a labelled button; hints shown as `<kbd>` in the button and in `title`):

| Key | idle | playing | recording | processing | reviewing / no-voice / error |
|-----|------|---------|-----------|------------|------------------------------|
| `Space` | `Nghe câu mẫu` (plays ×repeat, then auto-records) | stop → idle | stop recording early → processing | ignored | `Nghe câu mẫu` (new attempt) |
| `R` | `Ghi lại` (skip listening) | ignored | ignored | ignored | `Ghi lại` |
| `←` / `→` | previous / next sentence | previous / next (stops) | ignored | ignored | previous / next |
| `O` | play original once, no recording follow-up | ignored | ignored | ignored | play original once |
| `M` | disabled until a recording exists | — | — | play your recording | play your recording |
| `B` | disabled until a recording exists | — | — | — | original then yours |
| `I` | toggle IPA | same | same | same | same |
| `T` | toggle `Dịch` for the current sentence | same | same | same | same |

Rules:
- Shortcuts are active only on S3 and are ignored when focus is in `input`, `textarea`, `select`, a `role="combobox"/"listbox"` element or inside an open `role="dialog"`; `Sửa câu` edit mode therefore disables them.
- Mouse-clicked buttons release focus (`blur()` on pointer-up) so `Space` goes back to the global action; a button focused with `Tab` keeps native `Space`/`Enter` activation. This is what makes both "30 sentences with mouse only" and "keyboard only" possible.
- Mapping to the XState machine (PLY-02, own file): `idle → playing → recording → scoring → reviewing`, error branches `noVoice` and `error` (retry → `recording`). In P1 `scoring` is the upload-processing step (D-05) and renders State 4; Phase 3 attaches scoring without changing the machine shape. UI components read `state.value`/`state.context` only; no UI logic in the machine file.
- Auto-record: after the last repetition ends, recording starts immediately with countdown = sentence length × `recordFactor`; silence ≥ 1 s after speech has begun, or `Space`, stops early (REC-01). Padding 100–200 ms around the sample (`Lesson.padMs` 150).
- Recording upload sets `saveForEval=false` unless the user pressed `Lưu clip cho eval` for that attempt; that button re-sends/flags the same attempt (planner decides endpoint behaviour, D-09).
- Backend error during upload: toast (Sonner, top-right, persistent until dismissed) with action `Thử lại`, panel stays in the `error` state, the blob is retained so `M` and retry work (REC-03).
- Opening S3 selects the first sentence without a voiced attempt (PLY-04); if none, the first sentence.
- Never block the UI on a model: P1 practice needs no model (D-01); only `Mất chữ cuối?` recomputes one sentence and shows a pending state on its button.

Accessibility: banners `role="status"`/`"alert"` as above; state panels announce changes via an `aria-live="polite"` region (chip text); level meter has `aria-label` and is `aria-hidden` for per-bar animation; `SegmentedProgress` has a text equivalent; icon-only buttons have `aria-label` + `title` with the shortcut; colour never carries meaning alone (every status has text).
